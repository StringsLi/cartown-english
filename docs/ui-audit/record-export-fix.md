# 录音导出调试记录（2026-10-04）

## 发现与修复

- 当前 uni-app 运行时 `createInvoker` 会用 `setTimeout` 延迟普通 `tap` 回调。微信文件分享要求用户点击时同步调用。
- 录音页的发送按钮改为原生按钮，使用 `data-eventsync="true"`，直接调用分享，保留准备文件后再次点击的流程。
- 导出、备份和导入失败时保留可见错误原因，区分取消、手势限制、空间不足、文件缺失和平台不支持。避免通用 Toast 隐藏问题。
- 单条音频和 JSON 备份仍按原始内容导出，不更改已有录音。

## 验证

- 使用独立合成录音文件，在微信开发者工具中通过真实按钮准备单条 MP3 和全部录音 JSON 备份。
- 同步发送按钮不再收到手势限制，原生接口返回 `shareFileMessage:fail 开发者工具暂时不支持此 API 调试，请使用真机进行开发`。
- 回归测试执行已安装的 uni-app 事件调度器，验证普通 tap 延迟会失去手势，而同步按钮保留手势并调用分享。
- 音频字节、MP3/WAV 格式、备份恢复、取消/文件写入失败、安全清理、H5 下载及类型检查通过。
- 测试只使用合成文件，测试后恢复模拟器原始学习数据；未向聊天发送任何录音。

## 待真机确认

iPhone 微信开发版需重新扫码，点“导出音频”后再点“发送文件到微信聊天”，确认出现聊天选择界面并发送成功。开发者工具无法验证最后一步。
